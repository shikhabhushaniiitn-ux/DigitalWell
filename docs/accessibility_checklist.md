# Accessibility checklist

Use this checklist during implementation review and genuine student testing. Record issues and retest after changes.

- [ ] Navigate every section, input and link using keyboard only; verify a visible focus indicator.
- [ ] Confirm sidebar controls and form fields have clear labels and logical tab order.
- [ ] Check heading order and page titles; avoid using visual formatting as the only structure.
- [ ] Verify text contrast against backgrounds and do not use color alone to communicate state.
- [ ] Zoom to 200% and check that content remains readable without horizontal scrolling at common viewport widths.
- [ ] Test mobile layout with narrow screens and larger text settings.
- [ ] Ensure external links use descriptive labels and are distinguishable from body text.
- [ ] Check screen-reader announcements for filters, comparison results, buttons and validation warnings.
- [ ] Keep language plain, define unfamiliar terms and split instructions into numbered steps.
- [ ] Provide meaningful alt text for any screenshots added; redact names, notifications, email addresses and account identifiers.
- [ ] Check that screenshots are not the only way to understand a procedure.
- [ ] Test browser/device zoom, high-contrast or forced-colors settings where available.
- [ ] Ask participants about access needs without asking for diagnoses; offer an equivalent non-screen-reader testing option.

This is a practical checklist, not a claim of WCAG conformance or a completed audit.
